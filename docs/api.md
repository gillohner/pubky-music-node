# Native API (`/v1`)

The node also serves a built-in browser controller at `/` (one static page over this API: browse,
search, play to any zone or in the browser itself, queue, playlists, discover, settings).

HTTP + WebSocket served by `pm-node serve` on `[api] listen` (default `127.0.0.1:7788`).
Set `[api] token` to require `Authorization: Bearer <token>` (or `?token=` on the WebSocket).
Without one, a node listening beyond localhost makes its own on first start (`<data_dir>/api-token`, 0600); a documented placeholder such as `change-me` is never used as the token. Remote access by pubkey (M5) wraps this API.

| GET | `/v1/library/tracks/{id}/download` | `?format=aac\|mp3\|opus&bitrate=64–320` | a download for a phone or laptop (STEWARD-DOWNLOADS.md). The original by default, or a transcode (AAC in M4A, MP3, Opus in Ogg; default 256 kbit/s, Opus 160). Resumable: `Range` (one range or a suffix), `If-Range` on the `ETag`, `If-None-Match` gives 304, 416 past the end. `Content-Disposition: attachment` with the file name. Listeners may download what they may play. Files not on the node's disk (a WebDAV share, a drive) and every transcode are written once to `<data>/downloads/` (capped by the `downloads.cache_mb` setting, default 2048, oldest out first). Transcodes need ffmpeg (`downloads.ffmpeg` setting, else on the PATH): 501 without it, 502 when it fails. At most one transcode per CPU runs at once (503 after a minute's wait for a slot), each within a time limit (a minute plus a quarter of the track's length, at most 3 h; the `downloads.transcode_timeout_s` setting overrides it): past it ffmpeg is killed and the answer is 504. Files are read in 256 KiB chunks from where the range starts, never whole; a file bigger than the cache answers 507. A share or drive file is fetched with no total limit (up to 6 h) but given up on when the share sends nothing for 30 s (504); a partial copy or transcode never stays in the cache, even when the client goes away. The browser stream (`/v1/library/tracks/{id}/file`, `inline`) and Subsonic `stream`/`download` answer the same way, from the file or its cached copy |

Collections, reviews, listens, bookmarks and tags live in the node and sync to the user's homeserver as
pubky-social-specs v1 objects (ADR 0014) when the node has a session: a collection is a social
`collection` (private draft, also published while public; no size cap), a rated review a music `review`,
a text-only review a social note, a play a music `listen` under the root the history setting picks, a
bookmark a v1 bookmark, a tag a v1 tag. Collection items are music URLs or public Pubky posts. Times in
the music objects are microseconds; durations (`*_ms`) milliseconds.

Queues (items and repeat mode) are saved per zone on every change and restored, stopped, when the node restarts. Queue item URIs: `track:<library id>`, a local path, `file://`, or `http(s)://` (internet radio and direct file URLs; M3U/PLS playlist URLs are followed to their first stream; lossy streams mark the decode stage `Lossy`; ICY titles arrive as `now_playing.stream_title`). Subscription streaming services add schemes later.
Every `ZoneState` carries `now_playing.signal_path`, so a controller can render the chain for any zone. It also carries `now_playing.format`, what is arriving for the track: `{codec, bitrate_kbps?, lossless, service, tier?, preview}` (`codec` like `FLAC`, `MP3`, `DSD`; `service` like `library`, `tidal`, `stream`; `tier` is the service's quality tier where it has one). The decoded rate and bit depth are `now_playing.source_format`, and what the zone plays is `output_format`.
Types live in `pm_api::types`; a Rust client reuses them.

## OpenSubsonic (`/rest/*`)

The same server also speaks the Subsonic API (XML by default, JSON with `f=json`) for existing clients: Symfonium,
Feishin, Amperfy, play:Sub, Supersonic. Log in with `[api] subsonic_user` (default `pubky`) and the
API token as the password (token auth `t`+`s` or plain `p`). Only a node listening on localhost runs without a token; on any other address the node makes one (`<data_dir>/api-token`) when none is set.

Implemented: `ping`, `getLicense`, `getOpenSubsonicExtensions`, `getMusicFolders`, `getArtists`,
`getIndexes`, `getArtist`, `getAlbum`, `getMusicDirectory`, `getAlbumList(2)` (newest, random,
alphabetical, byYear), `getSong`, `getRandomSongs`, `search2/3`, `stream`/`download` (original
file, `Range` supported and read in chunks as for `/v1/library/tracks/{id}/download`, no transcoding), `getCoverArt`, `getPlaylists`, `getPlaylist`,
`createPlaylist`, `updatePlaylist`, `deletePlaylist` (the same playlists as `/v1`, so tracks need a
canonical identity), `scrobble` (private activity), `startScan`, `getScanStatus`,
`getLyrics` (plain text by artist and title) and `getLyricsBySongId` (OpenSubsonic `songLyrics`, timed lines when the source was),
`jukeboxControl` (drives one of the node's zones from a Subsonic client: `set`/`add`/`clear`/`remove`/`shuffle`/`start`/`stop`/`skip`/`setGain`/`get`/`status`; `?zone=<id>` picks and remembers the zone, otherwise the first by name), plus empty
answers for info calls. Ids: songs are track ids, albums `al-<id>`,
artists `ar-<id>`, playlists `pl-<id>`.
